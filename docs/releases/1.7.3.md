# 1.7.3

Fix the missing rename prompt for **opted-in Excalidraw dual-mode Markdown
pastes**, without removing drawing protection globally.

Add `allow-paste-image-rename: true` to the note's YAML frontmatter, switch to
Markdown mode, and paste one raster image above `# Excalidraw Data`. Automatic
renaming and the ordinary rename dialog are supported after verifying the native
insertion, source text, image bytes, and absence of shared/drawing references.
Default behavior is unchanged without this explicit opt-in.

- Close all Excalidraw/Canvas panes before pasting; unsaved parallel scenes cannot
  be verified. Large, malformed or ambiguously encoded textual data also refuses
  the rename rather than risking shared references.
- Drawing mode, batch commands, conversion, and Cancel and Delete remain protected.
- Shared/existing images, multi-file or unverified pastes, SVG/PDF files, stale
  prompts, modified source text, and ambiguous references are left unchanged.
- The current note’s conventional same-basename PNG/SVG exports (including light/dark variants) are reserved during
  filename allocation. Attachment directories never change.
- Requires the native editor event APIs in Obsidian 1.1.1+ for this opt-in path;
  the plugin's existing minimum version and ordinary Markdown behavior remain.
- PR #124's independent logging proposal and the whole-vault experiment are not
  included in this fix.

Verified in updated native Obsidian **1.14.5** with Excalidraw **2.29.0**:
manual and automatic body renaming, normal-note controls, default-off behavior,
drawing-mode exclusion, image hashes, drawing reopen, and SVG export.
205 regression tests and 20 release-policy tests pass. Typecheck/build pass;
Community ESLint remains **0 errors, 35 warnings**, with no new suppressions.
The actual remote Community scan is not claimed passed.
