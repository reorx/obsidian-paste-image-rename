# 1.7.0

This minor release brings safer attachment handling, more flexible filename patterns,
an image-link conversion command, and an optional action for discarding a verified
new insertion.

## Highlights

- **Safer automatic and batch renaming.** Automatic handling waits for a new parsed
  reference in the original Markdown note, including delayed insertions. Batch
  renaming handles mixed embeds and repeated references without renaming the same
  attachment twice. Renames are serialized, shared links use Obsidian's link updates,
  and repeated batches retain already-conforming numbered names.
- **Preview before a manual batch.** Changed inputs invalidate the preview. The
  batch checks previewed file identities and names before its first rename, stops
  on errors, and reports partial progress. Closing a running batch stops subsequent
  work; completed renames are retained.
- **More naming controls.** Use the original attachment stem in the prompt, choose
  the input selection/caret position, pad duplicate numbers to 1–12 digits, and
  optionally share one duplicate counter across extensions in the same folder.
- **Richer filename templates.** Added original-attachment-name variables, Unicode
  filename slugs with casing/separator options, nearest-heading variables, UUID/HEX
  values, an explicit `{{fileExt}}` token without a doubled final extension,
  `{{DATETIME:format}}`, ordered named-variable fallbacks, and conditional separators.
  Numeric zero and false frontmatter values are preserved. Existing DATE and
  frontmatter syntax remains supported; DATETIME's percent directives are limited
  to the documented hour/minute/second compatibility forms.
- **Convert Markdown image links to wiki embeds.** A separate command previews
  supported local inline images, preserves numeric dimensions, and applies changes
  in one undoable editor transaction. It skips descriptive alt text, titles,
  reference-style images, remote URLs, ambiguous syntax, and protected content.
  Conversion never renames, moves, or deletes files and never runs automatically.
- **Optional Cancel and Delete.** A manual rename prompt can discard a verified
  new, single-file native paste/drop: remove only that insertion's link, save and
  verify the note, then move the unchanged image to recoverable vault `.trash`.
  Ordinary Cancel, Escape, and dismissal leave the insertion and file intact.

## Safety and scope

- Turn on Obsidian's **Automatically update internal links** before renaming. The
  plugin blocks renames when that setting is explicitly disabled.
- New **Excluded folders** settings protect automatic handling of managed folders.
  Temporary/hidden files are ignored; invalid extension filters pause automatic
  handling until corrected. Unreferenced creations and sync-style restores with
  pre-existing references are left unchanged. Not every importer can be identified.
- **Renaming changes filenames only and preserves the existing directory.** Paths,
  traversal, destination routing, and folder creation are unsupported. Configure
  new-attachment placement in Obsidian's own Files and links settings. The separate,
  explicitly selected Cancel and Delete action is the only local-trash exception.
- **Canvas and Excalidraw drawing sources are intentionally excluded** from
  attachment tracking, rename prompts, batch commands, and link conversion,
  including recognized Excalidraw Markdown drawings. This release does not add
  Canvas or Excalidraw integration or certify ownership of assets referenced from
  ordinary Markdown notes.
- **Cancel and Delete is deliberately conservative.** Turn off Auto rename to use
  it. It requires a trusted single-file gesture, identical clipboard/file bytes,
  an exact new reference, and unchanged source/file state within 30 seconds. It
  supports verifiable Markdown-plus-raster-image vaults; Canvas, Excalidraw, SVG,
  other unsupported containers, shared/ambiguous references, dirty competing
  editors, and unverifiable syntax refuse deletion. A paste that also creates an
  attachment folder is ineligible. Verification is bounded to 2,000 files and
  2,000 folders, 200 MB of scanned content, 20 MB per file, and 2 million characters
  per note (Markdown files over 4 MB are rejected). See the README for all guards.
- **Undo after discard restores text only, not the trashed image.** Restore the
  image separately from the vault's `.trash` folder. Failed verification keeps the
  attachment; uncertain trash results are never automatically retried, and there
  is no permanent-delete fallback. Third-party private state and external apps are
  outside the ownership checks.

## Compatibility and verification

- The manifest's existing minimum Obsidian version remains **0.12.0**. Optional
  image-link conversion checks for the editor transaction API (0.13.0+); Cancel
  and Delete requires Obsidian **1.1.1+** and the required public editor APIs.
  Ordinary rename's exact-reference repair uses the legacy `replaceRange` API when
  transactions are unavailable, applying validated ranges from last to first.
- The release passes **159 automated regression tests**, TypeScript checks, ESLint,
  and a production build. Test bundles and source maps are not release assets;
  bundled third-party license notices are included in `main.js`.
- Native verification was performed in isolated vaults on **Linux with Obsidian
  1.14.4**. It includes saved-link/file-byte checks, template and numbering cases,
  conversion/drawing-source guards, and successful/refused discard flows with
  text-only Undo and manual trash recovery. This is targeted coverage, not a
  certification of every feature or of macOS, Windows, or mobile behavior. Native
  discard testing used genuine single-PNG file clipboard paste; other clipboard
  encodings, every raster format, and drag/drop are not independently certified.
  The final legacy-editor compatibility branch is covered by automated regressions;
  a native Obsidian 0.12.x runtime was not tested.
