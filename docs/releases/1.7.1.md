# 1.7.1

A behavior-preserving maintenance patch for Community review. Filename handling,
settings/defaults, native paste/drop, link updates, and recoverable local-trash
safeguards remain unchanged. The separate whole-vault experiment is not included.

- Remove the runtime package.json require, its undescribed lint-disable comment,
  and startup/debug console.log output. Development diagnostics use console.debug.
- Replace the build-only builtin-modules dependency with Node's builtinModules.
  The generated bundle retains a build-time version marker for asset validation.
- Remove unnecessary async callbacks and type assertions; express optional
  promises and queue fallbacks without Promise boolean conditions.
- Move static error visibility into CSS classes with equivalent styling; normalize
  CSS to the official Stylelint configuration.
- Use the host window's cryptography for UUID generation with the same algorithm.
- Correct the manifest description typo and punctuation.
- Add the official Community ESLint and Stylelint tooling, lockfile, and regressions.

## Verification

- 175 runtime/regression tests and 20 release-automation policy tests pass.
- TypeScript, production build, and release-asset validation pass.
- Official ESLint plugin 0.4.2 with documented scanner settings: **0 errors,
  51 advisory warnings**. Official Stylelint config 0.1.0: **0 errors, 0 warnings**.
- No plugin-specific rule suppressions. Existing minimum Obsidian version 0.12.0
  remains unchanged. Runtime tests include an absent version-check API and the
  modern native-event observer path, including cancellation of prior proof.

The remaining advisories are documented in the
[Community review audit](https://github.com/reorx/obsidian-paste-image-rename/blob/1.7.1/docs/community-review.md). In particular, observer handlers
must not cancel Obsidian's native insertion, and the optional discard action must
continue using recoverable vault .trash. Historical published SDK declarations
also disagree with some current API-version annotations. This local result does
not guarantee a future Community scan or manual approval; the next submitted
scan will determine any further patch.
